# QA journal

A user-directed record of testing feedback and implementation adjustments made after the current implementation receives
approval.


## Purpose

The QA journal records only changes requested or confirmed by the human during the QA phase. It is not a plan, review,
or reconciliation artifact.


## Summary

When the human approves QA, place a concise summary of all QA changes and their reasons at the top of the journal,
immediately after the source implementation reference.


## Source implementation

Path to the approved implementation or its execution review.


## Changes

Add one subsection per user-directed change, in chronological order.


### Request

Record the issue or adjustment as reported by the human.


### Reason

Record why the change was made, including the observed behavior or expected outcome.


### Files modified

List every file created, updated, or deleted for the change.


### Verification

Record the focused quality gate, tests, or manual verification performed and the result.
